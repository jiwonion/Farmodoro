# 집중 보상과 작물 돌보기

## 사용 흐름

집중 → Coin 획득 → 작물 돌보기 → 수확으로 이어진다. 타이머는 집중 시간을 기록하고 기존 누적 60분 Coin 보상을 지급한다. 밭의 **집중으로 키우기** 버튼, 집중 대상 표시, 집중 성장 진행률과 타이머의 직접 작물 성장은 제거했다.

- Coin으로 씨앗을 구매하고 작물을 돌본다. 무료 물주기와 기존 성장·시듦·회복·세트 효과는 유지한다.
- 씨앗 선택 창은 작물별 수확까지 필요한 돌보기 단계를 안내한다.
- 수확물로 요리하고 음식을 판매해 얻는 Farm Money는 테마와 테마 밭 구매에 사용한다.
- 타이머의 농장 배경 옵션은 유지한다. 배경은 비활성이며 타이머와 버튼을 계속 사용할 수 있다.

## 적용

기존 마이그레이션을 079까지 적용한 다음 `080_retire_focus_farm_growth.sql`을 적용하고 프런트엔드를 함께 배포한다. 전체 순서는 075 → 076 → 077 → 078 → 079 → 080이다. 운영 DB에는 자동 적용하지 않았다.

080은 집중 대상 선택과 직접 성장 RPC를 종료한다. 기존 집중 성장 컬럼과 기록은 휴면 상태로 보존하고 응답에는 집중 대상과 직접 성장 정보를 포함하지 않는다. 이미 자란 작물의 성장 단계와 보유 Coin·Farm Money·씨앗·수확물, 집중 누적 시간과 지급한 보상도 보존한다. 작물에 남아 있던 부분 집중 초는 추가 성장으로 환산하지 않는다.

`record_my_focus_time`는 집중 시간과 Coin 보상만 처리한다. 이전 프런트엔드의 `record_my_focus_time_v2` 요청은 호환 API로 받되, 전달한 밭·작물 대상은 무시한다. 이전 집중 대상 선택 RPC는 `FARM_FOCUS_RETIRED` 오류로 종료한다. 배포 전 열려 있던 탭이 서버에 집중 시간을 보내더라도 작물을 직접 키우지 않는다.

## 저장과 복구

집중 이벤트는 사용자·타이머 클라이언트별 로컬 전송 대기함에 식별자와 집중 시간을 기록한다. 서버는 동일 이벤트의 집중 시간과 Coin 보상을 중복 적용하지 않는다. 이전 대기 이벤트에 밭·작물 대상이 남아 있어도 새 프런트엔드와 080 서버에서는 집중 시간과 Coin만 반영한다.

타이머 소유 기기의 최신 타이머 상태도 대기함과 함께 저장하고 전송 완료 후에도 체크포인트를 보존한다. 같은 탭의 새로고침이나 재접속에서는 최신 체크포인트로 이미 기록한 시간을 다시 적립하지 않는다. 휴식 시간과 다른 기기에서 표시만 하는 타이머는 추가 적립하지 않는다.

집중 시간과 Coin 보상은 같은 서버 거래로 처리한다. 브라우저 저장소가 차단되거나 비워진 경우에는 로컬 복구 정보가 유지되지 않을 수 있다.

SQL 테스트는 `@electric-sql/pglite`가 필요하며 별도 설치 경로를 `PGLITE_MODULE`로 지정할 수 있다. 080 적용 후 집중 시간 기록·Coin 보상·중복 요청·이전 API 호환과 직접 성장 종료, 기존 심기·Coin 돌보기·물주기·수확 동작을 검사한다. 운영 Supabase 연결 검증을 대신하지 않는다.
