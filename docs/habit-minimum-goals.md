# 습관 최소·최대 목표

습관 등록·수정에서 기존 이름을 기본 목표로 쓰고, 바쁜 날에도 할 수 있는 최소 목표를 선택해서 추가한다. 최소 목표 이름이나 최소 집중시간 중 하나만 지정해도 기존 목표는 최대 목표가 된다. 최소 이름을 비워 두면 화면에는 기존 습관 이름을 사용하고 최소·최대 표시와 시간으로 구분한다.

- 최소·최대 달성 모두 습관별 하루 총 1 Coin이다. 최소 목표를 설정하지 않은 습관도 같다.
- 최소에서 최대로 바꾸거나 최대에서 최소로 바꿔도 Coin은 추가 지급하거나 회수하지 않는다.
- 선택한 단계를 다시 누르면 완료를 취소하고 실제 지급한 Coin을 회수한다.
- 각 목표 앞의 체크박스로 완료하며 한 날짜에는 최대·최소 중 하나만 선택된다. 다른 단계를 체크하면 기존 단계에서 전환된다. 최대·최소 목표가 있는 습관은 중복된 메인 제목을 표시하지 않는다.
- 두 단계 모두 연속 기록과 월간 달성률에 완료한 하루로 반영한다. 월간 달력은 단계를 구분한다.
- 최소 달성은 연한 파란색으로, 최대·일반 달성은 진한 파란색으로 잔디를 채운다. 최소 달성도 월간·주차별 달성률과 꾸준히 지킨 습관의 순위에서 예정된 날짜의 완료 1회로 동일하게 집계한다.
- 목표 집중시간을 쓰는 습관은 최소 목표에도 별도 집중시간을 선택해서 지정할 수 있다. 예를 들어 최소 5분, 최대 25분으로 저장한다. 최소 시간은 1~9999분이며 기본 최대 시간과 선택한 모든 요일의 최대 시간보다 짧아야 한다.
- 최소 집중시간을 지정하면 최소·최대 목표의 집중 타이머를 각각 시작할 수 있다. 선택한 목표의 시간을 채우면 해당 단계로 완료한다. 최소 달성 후에도 최대 목표를 위한 집중을 시작할 수 있고, 두 타이머는 그날 누적된 습관 집중시간을 함께 사용한다.
- 최소 집중시간을 비워 두면 기존처럼 최소 목표는 수동으로 완료하고, 집중 타이머는 최대 달성으로 처리한다.
- 기존 기록과 과거 지급액은 소급해서 바꾸지 않는다. 과거에 2 Coin을 받은 완료는 단계를 바꿔도 지급액을 유지하며, 완료를 취소할 때 실제 지급한 2 Coin을 회수한다. 취소한 뒤 다시 완료하면 새 기준인 1 Coin을 지급한다.

`minimum_title`은 기존 습관 이름과 같은 서버 암호화를 사용한다. 날짜별 `completion_level`과 지급액은 완료 RPC가 관리하며, 일반 동기화가 덮어쓰지 않는다. 중복 클릭을 막고 저장 오류 때 서버 기록과 지갑을 다시 읽는다.

`minimum_focus_minutes`는 선택 사항인 정수 열이다. 시간형 습관에서는 별도의 최소 목표 이름 없이도 저장할 수 있다. 예를 들어 습관 이름이 영어 공부하기이고 최소 5분·최대 25분이면 두 단계 모두 영어 공부하기로 표시하고 시간으로 구분한다. 기본 시간·요일별 시간·반복 요일을 수정할 때도 최소 시간이 최대 시간을 넘지 않도록 서버에서 검사한다. 기존 습관은 `null`을 유지한다. 선택한 단계는 타이머의 `activeFocus.completionLevel`과 `runtime.completionLevel`에 담아 기기 간 동기화한다. 단계가 없는 과거 타이머는 최대 목표로 이어진다.

## 적용 순서

기존 104까지 적용한 DB에 `supabase/migrations/105_habit_one_coin_reward.sql`을 먼저 적용한 뒤 클라이언트를 배포한다. 이전 버전의 DB는 아직 적용하지 않은 마이그레이션을 번호 순서대로 적용한다. 최소 목표에는 091·092·093의 스키마와 RPC 변경이 필요하며, 105가 완료 RPC의 보상을 1 Coin으로 바꾼다. 기존 마이그레이션은 수정하지 않는다. 105는 기존 기록이나 지갑을 갱신하지 않고, 이후 새 완료에만 1 Coin을 지급한다. 단계를 바꾸는 요청은 기존 지급액을 유지하므로 Coin 거래를 만들지 않는다. 마이그레이션 작성과 로컬 검증은 운영 DB 적용이나 배포를 의미하지 않는다.

## 검증

`node --test tests/habit-tiers.test.cjs tests/sync.test.cjs tests/scenery-focus-sync.test.cjs`로 1 Coin 보상·단계 전환·실패 복구·계정 전환·집중 완료를 검증한다. `node tests/habits-ui-smoke.cjs`와 `node tests/habit-monthly-summary.test.cjs`는 실제 Chrome에서 입력·달성 버튼·기록·반응형 화면을 확인한다.

`node tests/habit-minimum-goals-sql.cjs`는 PostgreSQL/PGlite에서 091·092·093·105 마이그레이션과 보상 RPC를 실행한다. 이전 보상 정책의 호환성과 105 적용 후 일반·이름 있는 최소·시간만 있는 최소 목표의 1 Coin 한도, 단계 전환 시 지갑 거래 없음, 중복 완료, 취소·재완료, 과거 2 Coin·0 Coin 지급액 보존과 정확한 취소, 무료 패스 환불, 지갑 실패 시 원자성을 확인한다. 최소 시간의 범위·목표 관계·요일 변경 검증, 마이그레이션 재적용 시 기록·잔액 보존, 선택한 타이머 단계의 실제 JSONB 저장·읽기와 소유권도 확인한다. `@electric-sql/pglite`가 별도 경로에 있다면 `PGLITE_MODULE`로 지정한다. 로컬 SQL 검증은 운영 Supabase 연결 검증을 대신하지 않는다.
