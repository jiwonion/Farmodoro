# 모바일 로딩·저장 안정화·집중·일정 개선

2026-11-25. 로컬 구현과 검증 기록. 운영 DB와 웹 배포는 별도다.

## 로딩

기존 서비스워커는 약 65.5 MiB의 이미지·폰트·이전 풍경을 설치 때 한꺼번에 받았다. 설치 캐시는 공개 서비스 소개·처리방침을 포함한 HTML·CSS·JS·매니페스트 41개, 약 0.90 MiB로 줄였다. 그림·폰트는 실제 요청할 때 캐시한다. 이 수치는 사전 캐시 크기이며 휴대폰에서 측정한 시작 시간은 아니다.

스크립트는 실행 순서를 유지하는 `defer`로 읽는다. 2 MiB 폰트의 preload를 제거하고 인증 확인 전 화면을 `display:none`으로 두어 숨겨진 로그인 배경의 다운로드를 줄인다. 프로필·지갑·설정·생산성 읽기는 동시에 시작한다. 할 일과 설정을 읽으면 앱을 표시하고 농장은 그 뒤에 불러온다. 저장된 앱 화면이 있으면 느린 탐색은 1.8초 뒤 캐시로 표시하고 뒤에서 HTML을 갱신한다.

## 저장과 진단

기존 `saveState()`는 서버 저장 예약만 했다. 모바일 입력 직후 종료되고 요청이 실패하면 복구 사본이 없었다.

- 모든 생산성 저장 예약 전에 계정별 체크포인트를 기기에 동기적으로 기록한다. 마지막 서버 확인 내용·현재 내용·삭제 대기 ID를 보관한다.
- 실패한 쓰기는 2초부터 최대 30초 간격으로 다시 시도하고 네트워크 복귀 때 즉시 재시도한다.
- 재접속 시 새 서버 데이터를 기준으로 수정한 필드만 합친다. 다른 기기에서 삭제한 기존 항목을 되살리지 않으며 완료·보상·보관은 서버 RPC 결과를 따른다.
- 읽는 중 새 동기화 신호가 들어오면 다음 읽기를 예약한다. 실시간 변경은 기존 5초 음소거 대신 180ms 단위로 모아 읽는다.
- 상단에 서버 저장 완료, 기기 보관·재시도, 기기 저장 실패를 표시한다. 저장 공간 부족도 알린다.

설정에서 계정·기기의 최근 진단 200개를 JSON으로 내릴 수 있다. 저장·연결·복구·오류 종류·소요 시간을 남기며 할 일 내용·이메일·토큰·오류 원문·스택은 수집하지 않는다. [108 SQL](../supabase/migrations/108_sync_diagnostics.sql) 적용 시 기존 Supabase의 `sync_diagnostics`에도 제한된 메타데이터를 전송한다. 계정당 최대 500개이며 업로드할 때 14일이 지난 기록을 정리한다. 업로드가 없는 계정은 다음 업로드 또는 운영 정리 전까지 오래된 기록이 남을 수 있다. 사용자는 자기 기록만 읽고 진단 실패는 작업 저장을 막지 않는다.

기기 저장소를 지운 경우나 다른 기기의 아직 전송되지 않은 내용을 복구할 수는 없다. 같은 필드의 동시 편집은 마지막 서버 반영 값이 적용된다. 별도 탭의 미전송 변경을 합치는 분산 편집 시스템은 아니다.

진단에는 무작위 기기 ID도 남겨 같은 계정의 휴대폰·태블릿·컴퓨터 기록을 구분한다.

## 집중탭

사진·풍경 배경, 배경 업로드, 기본 음악과 재생 표시, 집중 항목 선택기를 제거했다. 화이트·다크 테마의 토마토 타이머, 진행 표시, 시간 설정·시작·일시정지·종료·전체 화면을 제공한다. 움직임 줄이기를 존중한다.

오늘·집중탭은 같은 토마토 타이머 하나를 공유한다. 항목/그냥 집중 선택과 할 일·습관의 개별 집중 버튼을 모두 제거했다. 누적 보상·종료 알림·기기 간 타이머 동기화는 유지한다. 이전 버전에서 이미 진행 중인 연결 세션만 마무리할 수 있게 호환 처리를 남긴다. 과거 업로드 파일과 프로필의 배경 경로는 보존하지만 앱에서 읽지 않는다.

습관의 기본·최소·요일별 목표 집중 시간 입력과 검증, 오늘·습관 목록의 목표 시간·누적 집중 표시, 공유 이미지의 시간 목표를 제거했다. 새 습관과 수정한 습관은 완료 체크 방식으로 저장한다. 이름을 가진 최소 목표와 완료·보상·과거 집중 기록은 유지하며 시간만으로 정했던 최소 단계는 새로 선택하지 않는다. 기존 완료의 최소 단계는 이력과 통계에 남고 첫 체크로 정상 취소할 수 있다. 과거 타이머 복구를 위한 데이터 열과 호환 함수는 보존한다. 이 변경에 추가 SQL은 없다.

## 반복 할 일과 달력

[107 SQL](../supabase/migrations/107_recurring_tasks_and_calendar.sql)은 일반 할 일의 날짜와 별도의 반복 규칙을 추가한다. 매일·지정 요일·매월 지정일, 시작일·선택적 종료일을 지원한다. 없는 29~31일은 그달 마지막 날을 사용한다. 하루 경계는 기존 앱과 같은 한국 시간 04:00다.

반복은 날짜마다 독립적인 할 일이다. 서버 읽기 때 도래한 날짜를 생성하며 두 기기의 동시 접근과 응답 유실 후 재시도에도 중복되지 않는다. 삭제한 날짜의 발생 키를 남겨 재생성을 막는다. 한 번에 규칙당 최대 366일을 생성하고 남은 날짜는 후속 읽기에서 처리한다.

달력은 실제 항목과 미래 반복 예정을 구분한다. 달력에서 기존 항목을 수정하고 반복을 중단·재시작할 수 있으며 새 할 일은 할 일 메뉴에서 등록한다. 예정에는 보상을 주지 않는다. 반복을 중단해도 기존 항목은 남고, 중단된 날은 재시작 시 소급 생성하지 않는다. 날짜별 항목 수정은 해당 날짜에만 적용한다. 과거 할 일은 기존 보관·30일 삭제 정책을 따른다.

월별 달력은 일요일부터 토요일 순서로 표시한다. 새 할 일은 오늘 날짜를 실제 입력값으로 지정하고, 폼 초기화·수정 시 테마 날짜 버튼도 함께 갱신한다. 날짜를 건드리지 않고 저장해도 달력에 반영되며, 직접 날짜를 지우거나 기존 날짜 없는 항목을 수정할 때는 날짜 없음을 유지한다. 107 미적용 환경에서는 일반 할 일을 날짜 없이 등록하는 기존 동작을 유지한다.

오늘 화면의 할 일도 같은 달력 데이터를 사용한다. 처음에는 오늘 날짜이며 날짜 선택·이전/다음 날·오늘로 복귀를 제공한다. 해당 날짜의 할 일과 날짜 없는 미보관 항목을 함께 보여주고, 보관된 날짜 지정 항목도 기존 보관 기간 동안 해당 날짜에서 확인할 수 있다. 미래 반복 예정은 표시만 하며 완료·수정할 실제 항목이나 저장 데이터로 만들지 않는다. 그룹 필터·공유 이미지·새 항목의 기본 날짜도 선택한 날짜를 따른다. 타이머의 오늘 할 일 집계와 습관은 실제 오늘 기준을 유지한다. 계정 전환과 재접속 시 조회 날짜는 오늘로 돌아온다. 이 변경에 추가 SQL은 없다.

운영자 요청으로 Google 캘린더 연동을 제거했다. 달력에는 파머도로 할 일과 반복 예정만 표시한다. Google 연결·일정 조회·수동 추가 링크와 관련 모듈·스타일·사전 캐시를 제거하고 기본 Google 로그인은 유지했다. [연동 제거 기록](google-calendar.md)을 참고한다.

## 밭 하나로 줄이는 검토

현재 규칙은 무료 심기 → Coin 성장 → 수확이다. 시간 성장·시듦·물주기가 없어 네 밭이 재화 효율을 올리지는 않는다. Coin을 여러 작물에 나누면 개별 완성이 늦어질 수 있다. 수집 진척과 조작 단순화를 우선하면 단일 밭이 타당하다. 네 밭의 이점은 여러 작물을 미리 골라두는 편의와 장면 다양성이다.

권장안은 신규 심기를 한 밭으로 제한하고 기존 슬롯의 작물은 그대로 성장·수확하게 두는 전환이다. 성장도·수확 가능 상태·도감·Coin을 보존한다. 기존 작물은 별도 목록에서 접근하고 모두 수확한 뒤 단일 밭으로 합친다. 서버 슬롯 제한과 기존 클라이언트 요청도 함께 바꿔야 한다. 이번에는 검토만 했으며 슬롯과 운영 데이터는 변경하지 않았다.

## 적용과 검증

106까지 적용된 DB에 107, 108을 순서대로 적용한 뒤 웹 파일·서비스워커 v414을 배포한다. 107 미적용 시 일반 할 일은 계속 저장되며 날짜·반복 생성은 준비 중 안내를 표시한다. 달력의 할 일 추가 버튼은 제거했고 새 항목은 할 일 메뉴에서 등록한다. 기본 Google 로그인 외의 Calendar API 권한 요청은 사용하지 않는다. 공개 소개·처리방침 배포는 [게시 기록](privacy-release.md)을 따른다. 실제 운영 기기의 진단에서 `app_ready`, 저장 실패·복구·실시간 연결 실패를 확인한다.

검증: 기존·신규 테스트 252개 통과. 별도 브라우저에서 입력 직후 전송 실패 → 새로고침 → 복구 → 자동 재시도, 다른 기기의 완료 보존, 날짜·반복 폼, 320/390/768/1366px 달력과 진단 내용 제한을 확인했다. 달력의 새 할 일 추가 동작과 Google 연결·내보내기 링크가 없고 Calendar API 요청도 없는지 확인했다. 모의 인증에서 기존 Google ID 토큰 로그인 흐름을 확인했으며 실제 계정 로그인은 실행하지 않았다. 공개 서비스 소개·처리방침의 320/390/1366px 표시와 인증 없이 열림, 서비스워커 문서 격리와 404 처리를 확인했다. Postgres 호환 테스트에서 중복 발생 방지·월말·요일·중단/재시작·삭제 후 재생성 방지·암호화·계정 권한·탈퇴 연쇄 삭제·진단 500개 제한을 확인했다. 타이머는 기존 검사에서 320~2560px 화이트·다크 테마와 밤새 경과 복구·종료 알림을 확인했고, 이번 브라우저 검사에서도 오늘·집중탭 간 상태 유지를 확인했다.
