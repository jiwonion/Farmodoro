# 농장 개편 정산과 이전 기능 종료

2026-10-07. 우편함과 운영자 전체 업데이트 우편, 주방, 농작물, 용품, 밭 스킨을 종료하고 단일 풍경 성장으로 전환한다. 기존 Coin·Farm Money 잔액과 배경 테마 소유권, 할 일·습관·집중 기록, 완성한 풍경, 주간 랭킹 점수는 유지한다.

## 한 번 지급하는 전환 보상

| 자산 | 재화 | 계산 기준 |
| --- | --- | --- |
| 남은 씨앗 | Coin | 남은 수량 × 씨앗 기준가 |
| 심어 둔 작물 | Coin | 씨앗 기준가 + 현재 성장 단계 |
| 수확물 | Farm Money | 수량 × (씨앗 기준가 + 완성 성장 비용) |
| 완성 요리 | Farm Money | 수량 × 기존 요리 판매가 |
| 미사용 용품 | Farm Money | 수량 × 용품 기준가 |
| 구매한 밭 스킨 | Farm Money | 원장에 기록된 실제 결제액 |

씨앗과 용품의 재고에는 구매·선물·무료 지급분이 섞여 있다. 이를 모두 잔여 수량의 기준가로 보상한다. 심은 작물의 성장도 무료 물주기와 유료 성장을 완전히 구별하지 못하므로 현재 성장 단계를 모두 인정한다. 수확물은 기존 대량 판매의 개당 기준가를 사용하되 소량 재고도 정산한다. 밭 스킨은 소유권만 있는 무료 지급분에 구매 환급을 만들지 않는다.

미수령 우편의 물품도 포함한다. 만료되었어도 원본에 남아 있는 미수령 물품은 전환 보상에 포함한다. 이미 수령한 물품은 재고에 포함되어 있으므로 우편에서 다시 계산하지 않는다. 미수령 판매 우편의 가격은 청구하지 않는다. 랜덤 박스는 생성할 때 이미 확정된 물품 ID를 사용하므로 아직 공개하지 않은 물품도 함께 정산한다. 양수 재고나 미수령 물품에 카탈로그가 없거나 미정 ID가 있으면 전체 전환을 중단하여 0원 정산으로 자산을 묶지 않는다.

원자료와 계산 결과를 계정별 영구 정산 기록에 보관한다. 정산 지급은 기존 임시 요청 캐시의 만료 여부와 무관하게 한 번만 처리한다. 환급은 지갑과 거래 원장에 반영하고 주간 랭킹 수익에는 더하지 않는다. 클라이언트는 서버가 반환한 결과를 보여주며 자체적으로 재화를 지급하지 않는다.

내 풍경 화면의 ‘농장 개편 정산 완료’를 펼치면 지급 Coin·Farm Money와 항목별 수량·금액을 볼 수 있다. 일반 성장이나 테마 구매로 화면을 갱신해도 펼침 상태를 유지하며 계정 변경 후 다른 계정의 정산 기록을 보여주지 않는다.

이미 사용한 프리패스로 완료한 할 일·습관을 나중에 취소하면 기존 수령 권리를 용품 대신 Farm Money로 정산한다. 전환 시점의 완료 주기를 비공개 환급권 기록으로 확정하고 완료 주기별 영구 지급 기록으로 중복 지급을 막는다. 새로운 완료에는 프리패스를 사용하지 않으며 이후 클라이언트가 과거 사용 여부를 바꿔도 새 환급권은 생기지 않는다.

## 종료 범위와 보관

화면·이벤트·클라이언트 상태에서 우편·주방·씨앗·수확물·용품·밭 스킨 기능을 제거한다. 이전 독립 모듈과 전용 스타일, 서비스 워커 캐시 연결을 제거한다. 구 버전 클라이언트도 관련 RPC를 호출하거나 테이블을 직접 조회할 수 없게 서버 권한과 realtime 연결을 종료한다. 테마 구매·장착은 `farm_theme`만 허용한다.

별도 역할에서 상속한 이전 테이블 읽기 권한도 제한 정책으로 차단한다. 사용자에게 상속된 이전 RPC 실행 권한이나 숨겨야 할 농장·집중 열 조회 권한이 남아 있으면 전체 전환을 중단하고 운영자가 권한 설정을 정리한 뒤 다시 적용한다.

기존 DB 테이블·구매 기록·우편 기록을 물리적으로 삭제하는 마이그레이션은 자동 승인 검토에서 비가역적인 삭제 위험으로 거절됐다. 해당 삭제를 수행하지 않으며 원본은 비공개로 보관한다. 정산 원자료도 별도 비공개 감사 기록으로 남긴다.

정산 원자료의 우편 사본은 해당 계정이 받은 우편으로 한정한다. 사용자가 직접 계정 탈퇴를 요청하면 본인 기록과 발신 우편 원문을 삭제하고, 다른 계정의 정산 원자료에 복사된 발신자·메시지 원문도 제거한다. 수신자의 정산 금액과 개인정보 없는 계산 근거는 유지한다. 전환 마이그레이션에서는 계정 탈퇴를 실행하지 않는다.

## 운영 적용

086~088까지 적용한 DB에 089를 적용하고 새 클라이언트를 배포한다. `send-push` Edge Function을 현재 종료 응답(410)으로 배포하거나 원격에서 제거한다. `dispatch-scheduled-push`는 타이머 종료 알림만 조회하는 최신 코드로 함께 배포하여 집중 타이머 예약 알림을 유지한다. 종료 이전 API를 호출하는 오래된 탭은 새 앱을 받아야 한다.

로컬 마이그레이션·검증 파일 작성은 운영 DB 적용이나 원격 배포를 의미하지 않는다. 실행 결과와 배포 여부를 별도로 확인한다. 과거 마이그레이션은 새 DB를 구성하는 순서와 기존 데이터 구조를 재현하기 위해 유지한다.
